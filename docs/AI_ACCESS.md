# Доступ ИИ к Dragonfyre через GitHub — без пересылки файлов в чат

**Приватный источник проекта:** https://github.com/Ybuuc/dragonfyre-horizon-rust

GitHub — источник собственного кода, инструкций и **небольших безопасных результатов проверок**. Google Drive может хранить только разрешённые для хранения объёмные внешние ресурсы/архивы/сборки, если для них задокументированы права, хеши и способ доступа. Текущий локальный рабочий каталог — **не** единственный источник проекта.

## Три входные точки для любого агента

1. [`AGENTS.md`](../AGENTS.md): обязательные правила разработки, ограничения, порядок приёмки и запрет объявлять неполную работу завершённой.
2. [`reports/AI_STATE.json`](../reports/AI_STATE.json): машинно-читаемые последние подтверждённые тесты и сборка, SHA-256, актуальные ограничения и ближайшее действие. Это **сводка**, а не гарантия полного порта.
3. [`CURRENT_STATUS.md`](../CURRENT_STATUS.md), [`ROADMAP.md`](../ROADMAP.md), [`CONTEXT.md`](../CONTEXT.md), открытые GitHub Issues (#1: survival E2E; #2: полный аудит/воспроизводимость).

Дополнительно: [`docs/BUILD_REPRODUCIBILITY.md`](BUILD_REPRODUCIBILITY.md), [`docs/RESOURCES.md`](RESOURCES.md), [`STAGE07.md`](../STAGE07.md) – [`STAGE10-SURVIVAL.md`](../STAGE10-SURVIVAL.md).

## Доступ из ChatGPT и других ИИ

- **ChatGPT с подключённым GitHub:** попросить «Открой приватный репозиторий `Ybuuc/dragonfyre-horizon-rust`, прочитай `AGENTS.md`, `reports/AI_STATE.json`, `CURRENT_STATUS.md` и Issues #1/#2, продолжи по следующему незакрытому пункту». Агент должен использовать авторизованный GitHub connector, а не делать выводы из памяти. Подключение/разрешения к приватному репозиторию должны быть у конкретного агента/аккаунта.
- **OpenCode Desktop / терминальный Codex:** открывать **рабочий git clone** репозитория, выполнять `git pull --ff-only` перед работой, читать `AGENTS.md` и отчёты, после работы `git commit` и `git push`. Для доступа к приватному repo на компьютере должна быть настроена Git-аутентификация. Другой ИИ-сервис не получает права GitHub автоматически из ChatGPT.
- **ИИ только с доступом к публичному вебу:** не сможет самостоятельно читать приватный репозиторий. Требуется авторизованный GitHub connector либо доступ к локальному клону; делать репозиторий публичным **не требуется**.

## Чекпоинт в main

Для передачи работы редактируйте `handoff` в [reports/AI_STATE.json](../reports/AI_STATE.json). Отдельный экспорт чата для этого не нужен. Входная команда приведена в [README](../README.md#для-ии-агентов-начните-здесь).

| Поле | Содержимое |
| --- | --- |
| `updated_at`, `status` | Момент последнего сохранения и состояние задания |
| `active_task`, `related_issues` | Текущий этап и ссылки на GitHub Issues |
| `work_ref` | Ветка, уже доступный в GitHub SHA кода или результатов и PR, если он открыт |
| `completed`, `verification` | Сделанные изменения, команды или ссылки и фактический результат проверок |
| `blockers`, `next_action` | Точный блокер и один следующий воспроизводимый шаг |

`work_ref.commit` указывает на уже существующий рабочий коммит, поэтому он может отличаться от коммита, публикующего сам чекпоинт. Для незавершённой ветки сначала опубликуйте код, затем запишите её ссылку в чекпоинте на `main`. В новом сеансе проверьте свежие коммиты в обеих ветках и связанные Issues. Обновляйте чекпоинт после каждого самостоятельного результата, чтобы ограничение сессии оставило как можно меньше работы без записи.

### Работа без файлов на ПК пользователя

- Подключите приватный репозиторий к облачному агенту через его GitHub-интеграцию. Чтение и публикация изменений возможны напрямую через GitHub. Если нужны тесты, агент может использовать свой временный облачный checkout.
- Сохраняйте исходники, патчи, скрипты, документацию и небольшие сводки в GitHub. Тяжёлые разрешённые артефакты храните отдельно со ссылками и SHA-256. Если нужный артефакт ещё доступен только локально, оставьте это в чекпоинте.
- Ссылка на приватный репозиторий сама по себе не выдаёт разрешения. Для игрового теста требуется доступ к среде Windows/Horizon, а для автономных Rust-тестов используется отдельный сценарий.

## Как получить последние локальные отчёты без копирования их в переписку

Новый Windows-скрипт [`scripts/sync-ai-state.ps1`](../scripts/sync-ai-state.ps1) **не требует GitHub CLI**; он использует установленный Git. Скрипт:

- читает только `apply-report.json` и `build-debug.json` из выбранного `outputs/native-reproduction/dragonfyre-native-*/`;
- сверяет SHA-256 собранного `horizon-client-debug.exe`, не загружая сам .exe;
- сохраняет существующий `handoff`. Вручную обновите его после интерпретации результата, включая следующий шаг и ссылку на рабочий коммит;
- сохраняет в `reports/AI_STATE.json` только allowlist полей (статус, число инъекций и модулей, SHA-256, размер, код возврата);
- **не добавляет в Git** пути локального ПК, полные logs, файлы игр, приватные данные, архивы, бинарники, переменные окружения или непроверенные папки `work/`;
- при запуске с `-Push` создаёт commit только для `reports/AI_STATE.json` и выполняет обычный `git push origin main` без force. При расхождении с remote push не пройдёт — нужно примирить изменения, не форсировать.

Выполнение из корня проекта:

```powershell
git pull --ff-only

# Предварительная проверка и обновление одного локального JSON:
.\scripts\sync-ai-state.ps1 -RunId dragonfyre-native-bi4vueka

# Опубликовать ту же безопасную сводку в GitHub:
.\scripts\sync-ai-state.ps1 -RunId dragonfyre-native-bi4vueka -Push
```

После следующей сборки агент может запускать `scripts/sync-ai-state.ps1 -Push` без `-RunId`, скрипт выберет самый свежий изолированный run с `build-debug.json`. **Параметр `-Push` является явным действием публикации; без него файл остаётся локальным.**

Для повторяемых тестов без `build-debug.json` необходимо отдельно добавить безопасный экспорт их отчётов — не считать их автоматически синхронизированными. `AI_STATE.json` не является заменой файловой проверки на компьютере.

## Что ещё не передано

- В момент первичного аудита локально было 27 неотслеживаемых подкаталогов `work/` (10 743 файла в них суммарно). Это в основном копии Horizon/временные сборки, но полный аудит авторских изменений и важного контента **не завершён**; каталог нельзя просто удалить.
- `outputs/` намеренно находится в `.gitignore`: крупные .exe, .hmod, логи, временные миры и кэши **не доступны удалённому агенту через GitHub**.
- Полный bootstrap pinned Horizon/mixins/toolchain, а также автоматический перенос разрешённых крупных ресурсов в Google Drive **пока не подтверждены**. Права на чужие архивы надо проверять до публикации.
- Вызов GitHub connector позволяет читать и редактировать GitHub, но **не открывает доступ к Windows-диску**. Изменения на диске другого ИИ появятся здесь только после `git push` или публикации отчёта.

## Стандартные действия агента

1. Перед работой синхронизировать GitHub, прочитать `AGENTS.md`, `reports/AI_STATE.json`, `CURRENT_STATUS.md`, Issues.
2. Использовать код из репозитория, не требовать повторной пересылки файлов, уже находящихся там.
3. Изменить исходники и выполнить реальные проверки; сохранять аргументы/статусы/хеши без секретов.
4. Обновить документы, Issue, code commit. Для проверки локальной сборки — запустить `sync-ai-state.ps1 -Push` при наличии локального Git и разрешённой публикации.
5. Перед заявлением об успехе проверить, что remote `main` действительно обновлён и `reports/AI_STATE.json` доступен через GitHub. Если доступ/авторизация отсутствуют, явно сообщить о блокере; не просить заново весь контекст вместо настройки доступа.

## Почему GitHub не освобождает место автоматически

`git push` копирует только git-tracked исходники. `.gitignore` исключает `outputs/`, compiled binaries, download/cache directories, поэтому они остаются локальными. Создан [`scripts/offload-to-drive.ps1`](../scripts/offload-to-drive.ps1) для переноса выбранных больших папок в **приватный Google Drive remote `gdrive:`**; сначала `List`, затем `Archive` с полным побайтным сравнением, и только отдельной подтверждённой командой `Prune` локальная копия может быть удалена. См. [docs/RESOURCES.md](RESOURCES.md). Скрипт ещё не запущен на ПК; папки не выгружены и не очищены.
