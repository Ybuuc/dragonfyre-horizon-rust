# Внешние ресурсы, хранение и воспроизводимость

## Где что хранить
- **GitHub**: собственные исходники Rust/Python/PowerShell, метаданные, конфигурации без секретов, документация, исправления и небольшие текстовые отчёты.
- **Google Drive**: разрешённые к хранению крупные оригинальные входные архивы, локально подготовленные релизные сборки, скриншоты/логи и резервные копии. Для каждого объекта фиксировать путь, имя, размер, SHA-256, версию, лицензионное основание и способ получения.
- **Локальная машина**: только необходимые для сборки/запуска файлы, рабочий профиль и небольшие временные каталоги.

## Безопасность и законность
Не публиковать сторонние игровые ресурсы или чужие бинарники в GitHub без права распространения. Не хранить ключи, cookies, данные аккаунта, миры пользователя, UUID с личными данными, токены доступа и пароли. Приватность репозитория сама по себе не заменяет проверку лицензии.

## Воспроизводимость
В документации сборки указывать версии Horizon, Rust, профили Cargo, команды применения mixins и упаковки hmod, хеши входных модов, список исключений. Если `work/stage09-journal/applied` — только генерируемое дерево, проверить наличие скрипта/патча, который полностью воссоздаёт его из отслеживаемых исходников. **Не исключать единственную копию изменений из Git!**

## Очистка
Очистку делать только после проверки загрузки в облако, контрольных сумм и пригодности восстановления. Пользовательские сохранения и единственные копии артефактов нельзя удалять без согласия.

## Реальное освобождение локального места

Важно: `git push` переносит только tracked файлы, а не большие локальные `work/` и `outputs/`, которые исключены `.gitignore`. Google Drive 500 ГБ через ранее настроенный **rclone remote `gdrive:`** — отдельное хранилище для разрешённых архивов и сгенерированных файлов. Загрузка в Google Drive не освобождает место сама по себе: после подтверждённой загрузки нужно удалить локальную копию.

Создан [`scripts/offload-to-drive.ps1`](../scripts/offload-to-drive.ps1) для отдельных каталогов внутри `work/` и `outputs/`. Его режимы:

- `-Mode List`: локально перечислить размеры подкаталогов `work/` и `outputs/`, ничего не передавать;
- `-Mode Archive -RelativePath 'work/stage07-build-4337axm1'`: `rclone copy` в `gdrive:Dragonfyre-Archive/dragonfyre/work/stage07-build-4337axm1`, затем **скачать потоково для сравнения** все удалённые файлы (`rclone check --one-way --download`) без размещения второй полной копии на диске; записать локальную квитанцию проверки `outputs/offload-receipts/`; оригинал оставить;
- `-Mode Prune -RelativePath 'work/stage07-build-4337axm1' -ConfirmDeletion DELETE_VERIFIED_LOCAL_COPY`: повторно скачать/сравнить байты с Google Drive, проверить наличие подходящей квитанции, неизменность числа/размера файлов, **только потом удалить конкретный локальный каталог**. Нельзя удалять любой `saves`, `playerdata`, `instances`, каталог с найденными секретами, символическими ссылками и т.д. `native/`, `.git`, корень проекта не являются допустимыми для переноса и удаления.

**Скрипт ещё не запускался на пользовательском Windows**, до результата нельзя считать файлы выгруженными. Сначала провести только `List`. Переносить прежде всего неиспользуемые сборочные копии и кэши. Приоритетный текущий отладочный клиент `outputs/native-reproduction/dragonfyre-native-bi4vueka` может потребоваться для игрового теста — не удалять до проверки. На активном ПК минимум оставить клонированные исходники, исполняемые инструменты и нужный профиль/миры.

Для `rclone` GUI возможно понадобится указать путь к его `rclone.exe` через параметр `-RcloneExe`. Требуется та же конфигурация `gdrive:`, которая была настроена пользователем. Нельзя подменять её чужим аккаунтом. Прежде чем загружать оригинальные моды, соблюдать условия их использования; Drive-архив должен оставаться приватным.
