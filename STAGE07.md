# Dragonfyre → Rust/Horizon: этап 07

Цепочка переносит три исходных задания из Dragonfyre 3C Beta. Два задания дают одну и ту же валюту, которую расходует третье. В исходных данных между ними нет формальной зависимости: обмен открывается при наличии монет. Условие не добавлялось искусственно.

| Исходный квест | Условие | Награда |
| --- | --- | --- |
| `5AFA5CB101E31BE4`, Crimson Radiance | иметь `cisco_mod:radiant_ruby` | 3 `cisco_mod:champion_coin` |
| `288608ED892DC5EB`, Red as a Ruby | иметь `cisco_mod:divine_core` | 2 `cisco_mod:champion_coin` |
| `2AE651270FD58200`, Plate of Honey Glazed Ham | сдать 2 `cisco_mod:champion_coin` | 16 `farmersdelight:honey_glazed_ham`, обмен повторяемый |

Из исходных SNBT проверены 461 ID квестов, 803 определения наград, ID задач и связи. У трёх заданий сверены предметы, количества, ID наград и признаки списания и повтора. Сводка с хешами глав: `outputs/native-stage-07/source-verification.json`.

Два пакета, `Dragonfyre-cisco_mod.hmod` и `Dragonfyre-farmersdelight.hmod`, регистрируют четыре самостоятельных ID предметов. Они используют модели из уже установленных ресурсов Minecraft. Порция ветчины восстанавливает 14 единиц еды, насыщение 21, складывается по 16 и возвращает миску. Эффект Nourishment, оригинальные изображения, рецепты для рубина и ядра и остальные предметы модов не входят в этот перенос. Сценарий выдаёт только стартовые рубин и ядро; монеты и порции игрок получает исключительно через квестовые операции.

Локальный владелец встроенного сервера читает `players/data/<UUID>.dat` либо свою резервную копию `.dat_old`. При смене владельца старая запись из `level.dat` не используется как профиль нового игрока; UUID для последующего сохранения привязывается к подключившемуся владельцу. Старые файлы не удаляются. Профиль, существующий только в старом общем снимке без подтверждённой привязки, требует отдельной миграции; уже ошибочно переписанное старой версией сохранение этот патч сам не восстанавливает.

Номер цикла обмена входит в идентификатор записи журнала. Повтор той же команды для того же цикла не начинает новый обмен. Следующий цикл доступен после получения награды за предыдущий. Экономика остальных квестов сохраняет прежний формат и идентификаторы операций. Идентификатор в сохранении без соответствующего журнала отклоняется.

Команды оператора (уровень 3):

```text
/dragonfyredev claim 5AFA5CB101E31BE4
/dragonfyredev claim 288608ED892DC5EB
/dragonfyredev submit 2AE651270FD58200 1
/dragonfyredev economy 2AE651270FD58200 1
/dragonfyredev claim 2AE651270FD58200 1
/dragonfyredev submit 2AE651270FD58200 2
/dragonfyredev claim 2AE651270FD58200 2
```

Если номер опущен, используется цикл 1. В новом мире с пятью заработанными монетами после двух завершённых циклов должно остаться 1 монета и 32 порции. При двух запросах сдачи для цикла 1 оба запроса обращаются к одной записи. Проверки используют отдельные папки игры, имена игроков и миры. Текущий статус проверок фиксируется в `outputs/native-stage-07/`.

## Результаты проверки в Horizon

Сборка с диагностикой завершилась успешно. Игра загрузила оба пакета предметов и отработала три отдельных запуска в одном тестовом мире: A → B → A. В цепочке использовались исходные ID предметов и обычные квестовые операции; подмена наград тестовыми данными была отключена.

| Проверка | Результат |
| --- | --- |
| Профили по UUID | B вошёл с пустым инвентарём и без прогресса A; получил 5 уровней и огниво за отдельный квест. При повторном входе A не получил ни этих уровней, ни огнива. На диске два разных файла игрока и два отдельных журнала. |
| Сдача и награда | Рубин и ядро принесли 5 монет. Каждый из двух циклов списал ровно 2 монеты и выдал 16 порций. Повторные команды для того же цикла не меняли количество; попытка начать второй цикл до получения первой награды отклонена. |
| Штатный перезапуск | A вернулся с 1 монетой, 16 порциями и сохранённой сдачей второго цикла. После получения второй награды осталось 1 монета и 32 порции, по 16 в двух стопках. В журнале A ровно шесть подтверждённых операций; в журнале B — одна. |
| Чтение файла и резерва | В отдельной проверке на настоящих файлах игрока старый путь воспроизвёл подмену B кэшем A. Новый путь прочитал собственные .dat обоих UUID, а после удаления тестового .dat B — его собственную .dat_old. |

Дополнительно прошли 34 теста движка квестов и независимая проверка повторного открытия журнала в другом процессе. Полный старый клиент этапа 06 потерял соединение до входа игрока, поэтому подтверждение причины дефекта опирается на отдельную проверку загрузчика. Пользовательские миры при испытаниях не менялись.

Расширенный сценарий из семи запусков также прошёл. В четвёртом запуске процесс принудительно завершён с кодом 86 сразу после записи намерения выдать вторую награду. При следующем входе Horizon восстановил операцию: у A было 32 порции и 1 монета, а повторные команды не дали третью награду и не списали монеты повторно. После нового входа B и затем A каждый сохранил свои предметы, опыт и прогресс.

Журналы и ответы игры: outputs/native-stage-07/quick-game-checks/ и outputs/native-stage-07/game-checks/ (в архиве — evidence/).

## Как повторить проверки

Из корня проекта на этой машине:

```powershell
python work/verify_stage07_source.py
python work/package_stage07_items.py
python work/build_native_stage07.py
python work/verify_native_stage07.py --quick
```

Полный сценарий без `--quick` добавляет контролируемое завершение процесса после записи намерения выдать награду. Старый клиент для сравнения можно явно указать через `--baseline --client ПУТЬ`. Для сборки нужны тот же снимок Horizon `66f3981f522b24c250b21523a70080965b940424`, официальный `horizon-mixins` и подготовленные ресурсы 26.3 для испытаний. В этой среде внешний GCC отсутствовал, поэтому повторная сборка использовала `work/prepare_stage07_cached_mimalloc.py` и `--cargo-config outputs/native-stage-07/build-overrides.toml`. Скрипт сверяет исходники зависимости с обеими стадиями и записывает хеш повторно использованной библиотеки.

Параметры еды сверены с [исходными значениями Farmer’s Delight 1.20](https://raw.githubusercontent.com/vectorwing/FarmersDelight/1.20/src/main/java/vectorwing/farmersdelight/common/FoodValues.java) и [регистрацией порционных блюд](https://raw.githubusercontent.com/vectorwing/FarmersDelight/1.20/src/main/java/vectorwing/farmersdelight/common/registry/ModItems.java).
